# Switch Case в JavaScript

## Синтаксис и структура
1. **Базовый синтаксис** — `switch (expression) { case value: statements; break; default: statements; }`.
2. **`switch`** — ключевое слово, начинающее конструкцию.
3. **`expression`** — выражение, значение которого сравнивается с case (может быть любым типом).
4. **`case`** — ключевое слово, определяющее значение для сравнения.
5. **`value`** — значение, с которым сравнивается expression (используется строгое сравнение `===`).
6. **`break`** — завершает выполнение блока switch (выходит из конструкции).
7. **`default`** — необязательный блок, выполняется если ни один case не совпал.
8. **`statements`** — код, выполняемый при совпадении с case.
9. **Отсутствие `break`** — приводит к "проваливанию" (fall-through) к следующему case.
10. **Группировка case** — несколько case подряд для одного блока кода.

## Сравнение в switch
11. **Строгое сравнение (`===`)** — switch использует строгое сравнение (без приведения типов).
12. **`case 1`** — не совпадает с `case '1'` (разные типы).
13. **`case true`** — совпадает только с булевым значением `true` (не с 1).
14. **`case null`** — совпадает только с `null` (не с `undefined`).
15. **`case undefined`** — совпадает только с `undefined`.
16. **Сравнение объектов** — сравниваются ссылки, а не содержимое.
17. **Сравнение массивов** — сравниваются ссылки.
18. **Сравнение с NaN** — `NaN === NaN` → `false`, поэтому `case NaN` никогда не сработает.

## Fall-through (проваливание)
19. **Fall-through** — когда код выполняется последовательно от совпавшего case до ближайшего break.
20. **Пропущенный break** — выполнение переходит к следующему case.
21. **Использование fall-through** — может быть полезно для группировки case.
22. **Опасность fall-through** — случайное выполнение нежелательного кода.
23. **Защита от fall-through** — всегда добавлять `break` (кроме осознанных случаев).
24. **Комментарий для fall-through** — `// fall-through` для пояснения намерения.

## Default блок
25. **`default`** — выполняется, если ни один case не совпал.
26. **Расположение default** — может быть в любом месте (обычно в конце).
27. **`default` без break** — также может проваливаться (если не в конце).
28. **Обязательность default** — необязателен, но рекомендуется для обработки неожиданных значений.
29. **`default` как fallback** — для значений по умолчанию.

## Вложенный switch
30. **Вложенный switch** — switch внутри другого switch.
31. **Break во вложенном** — break прерывает только внутренний switch.
32. **Метки (labels)** — можно использовать метки для выхода из внешнего switch.
33. **`break label`** — прерывает внешний switch (редко используется).
34. **Сложность вложенности** — ухудшает читаемость, лучше выносить в функции.

## Switch с диапазонами
35. **Диапазоны через switch** — эмуляция через `true` в выражении.
36. **`switch (true)`** — позволяет использовать условия в case.
37. **`case x > 10`** — работает, так как expression = true сравнивается с условием.
38. **Проверка диапазонов** — `case x >= 0 && x <= 10`.
39. **Комбинированные условия** — `case x > 0 && x < 5`.

## Switch с регулярными выражениями
40. **`switch (true)`** — для проверки регулярных выражений.
41. **`case /pattern/.test(str)`** — условие с регулярным выражением.
42. **`case str.match(/pattern/)`** — проверка совпадения.
43. **Комбинирование условий** — несколько проверок в одном case.

## Switch с объектами
44. **`switch (obj.prop)`** — сравнение свойства объекта.
45. **`case obj.prop`** — динамические значения.
46. **Сравнение объектов** — проверка ссылок (не содержимого).
47. **`switch (JSON.stringify(obj))`** — сравнение сериализованных объектов.
48. **Сравнение с `null` и `undefined`** — отдельные case для каждого.

## Switch и типы данных
49. **`case 'string'`** — строковое значение.
50. **`case 42`** — числовое значение.
51. **`case true`** — булево значение.
52. **`case Symbol('id')`** — символ (уникальное значение).
53. **`case BigInt(42)`** — BigInt значение.
54. **`case null`** — null значение.
55. **`case undefined`** — undefined значение.
56. **Смешанные типы** — разные типы в разных case.

## Switch в разных контекстах
57. **В функции** — `function fn(x) { switch(x) { ... } }`.
58. **В методе объекта** — `{ method() { switch(x) { ... } } }`.
59. **В классе** — `class { method() { switch(x) { ... } } }`.
60. **В цикле** — `for (...) { switch(x) { ... } }`.
61. **В IIFE** — `(function() { switch(x) { ... } })()`.
62. **В модуле** — `export function fn(x) { switch(x) { ... } }`.

## Альтернативы switch
63. **if...else if** — более гибкая конструкция (сравнение с любыми условиями).
64. **Объект-отображение (Object map)** — `const map = { 'case1': fn1, 'case2': fn2 }`.
65. **Map коллекция** — `const map = new Map([['case1', fn1], ['case2', fn2]])`.
66. **Тернарный оператор** — для простых условий (`condition ? value1 : value2`).
67. **Полиморфизм** — использование методов объектов.
68. **Стратегия (Strategy pattern)** — выбор алгоритма по ключу.
69. **Фабрика (Factory pattern)** — создание объектов по типу.
70. **Паттерн "Команда"** — инкапсуляция запросов как объектов.

## Производительность
71. **Скорость switch** — часто быстрее, чем if...else для многих case.
72. **Оптимизация движком** — switch может использовать таблицу переходов (jump table).
73. **Сравнение с объектом** — объект-отображение часто быстрее для большого количества case.
74. **Вычисление выражения** — expression вычисляется один раз (в отличие от if...else).
75. **Оптимизация в V8** — switch оптимизируется в байт-код.
76. **Влияние break** — break позволяет выйти без проверки остальных case.
77. **Влияние default** — default не замедляет, если не достигается.

## Отладка
78. **`console.log` в case** — вывод значений для отладки.
79. **`debugger` в case** — точка останова внутри case.
80. **Ошибки в switch** — забытый break → fall-through.
81. **Ошибка: неверное сравнение** — забытое строгое сравнение (case '1' vs case 1).
82. **Ошибка: default не достижим** — если все случаи обработаны.
83. **Ошибка: переменная вне switch** — объявление переменных внутри case (доступны во всем switch).
84. **Область видимости переменных** — `let` и `const` в case видны во всем switch.
85. **Решение: блоки в case** — `case 1: { let x = 10; } break;` (изоляция области).

## Продвинутые техники
86. **Динамические case** — `switch (expression) { case getValue(): ... }`.
87. **Вычисляемые case** — `case someVariable` (переменная в case).
88. **Case с функциями** — `case fn()` (вызов функции в case).
89. **Switch с итерацией** — перебор массива с switch внутри.
90. **Switch с обработкой ошибок** — `try...catch` внутри case.
91. **Switch в генераторах** — `yield` внутри case.
92. **Switch в async функциях** — `await` внутри case.

## Switch и логические операции
93. **Логическое ИЛИ (`||`) в case** — `case 1 || 2` → вычисляется как 1 (не два значения).
94. **Логическое И (`&&`) в case** — `case 1 && 2` → вычисляется как 2.
95. **Тернарный оператор в case** — `case x > 0 ? 1 : 2` (вычисляется значение).
96. **Группировка case** — `case 1: case 2: case 3: ... break;` (все три выполняют один код).

## Распространённые ошибки
97. **Забытый break** — выполнение продолжается до следующего break.
98. **Неверное сравнение типов** — `switch('1') { case 1: ... }` → не совпадает (строгое сравнение).
99. **`default` не в конце** — может привести к fall-through.
100. **`default` без break** — если не в конце, выполняется следующий case.
101. **Объявление переменных в case** — `var` видна во всем switch, `let` в блоке switch.
102. **Дублирование case** — `SyntaxError: Duplicate case label`.
103. **NaN в case** — никогда не совпадает (`NaN !== NaN`).
104. **Сравнение объектов** — `case {}` никогда не совпадет (новые объекты).
105. **Сравнение функций** — `case function() {}` никогда не совпадет (новые функции).

## Сравнение switch vs if...else
106. **Скорость** — switch быстрее при многих case (оптимизируется).
107. **Читаемость** — switch чище для множества значений одной переменной.
108. **Гибкость** — if...else позволяет сложные условия (диапазоны, логические операции).
109. **Строгое сравнение** — switch использует `===` всегда.
110. **if...else** — может использовать любые сравнения (`>`, `<`, `>=`, `<=`, `!=`, `!==`).
111. **Fall-through** — только в switch (в if...else каждый блок отдельный).
112. **default vs else** — аналог default в if...else.

## Примеры использования
113. **Обработка ошибок по коду** — `switch (error.code) { case 404: ... case 500: ... }`.
114. **Меню приложения** — выбор действия по команде.
115. **Обработка событий** — `switch (event.type) { case 'click': ... case 'keydown': ... }`.
116. **Состояния конечного автомата** — `switch (state) { case 'loading': ... case 'ready': ... }`.
117. **Парсинг данных** — `switch (type) { case 'json': ... case 'xml': ... }`.
118. **Обработка HTTP методов** — `switch (method) { case 'GET': ... case 'POST': ... }`.
119. **Обработка форм** — `switch (field) { case 'email': ... case 'password': ... }`.
120. **Обработка типов файлов** — `switch (extension) { case '.jpg': ... case '.png': ... }`.

## Рекомендации
121. **Всегда добавлять break** — чтобы избежать fall-through (кроме осознанных случаев).
122. **Добавлять default** — для обработки неожиданных значений.
123. **Группировать case** — для одинакового кода (`case 1: case 2: ... break;`).
124. **Использовать блоки для переменных** — `case 1: { let x = 10; } break;`.
125. **Комментировать fall-through** — `// fall-through` для ясности.
126. **Не использовать switch для диапазонов** — лучше if...else.
127. **Не использовать switch для объектов** — лучше Map или объект.
128. **Выносить сложную логику в функции** — для читаемости.

## Паттерны с switch
129. **Factory pattern** — создание объектов по типу.
130. **State pattern** — управление состояниями.
131. **Strategy pattern** — выбор алгоритма.
132. **Command pattern** — выполнение команд.
133. **Interpreter pattern** — интерпретация выражений.
134. **Visitor pattern** — обход структуры с разными действиями.

## Дополнительно
135. **`switch` в строгом режиме** — работает одинаково.
136. **`switch` в нестрогом режиме** — работает одинаково.
137. **`switch` с `eval`** — крайне не рекомендуется.
138. **`switch` с `with`** — запрещено в строгом режиме.
139. **`switch` в TypeScript** — поддерживается с типами.
140. **`switch` в JSX** — можно использовать в render-методах React.
141. **`switch` в Node.js** — полная поддержка.

## Производительность в деталях
142. **Switch vs Object lookup** — объект быстрее для > 10 case (в некоторых движках).
143. **Switch vs if...else** — switch быстрее для > 5 case.
144. **Влияние default** — минимально.
145. **Влияние вложенности** — незначительно.
146. **Оптимизация в JIT** — JIT компилятор оптимизирует switch в jump table.
147. **Предсказание ветвлений** — CPU предсказывает переходы.

## Отладка ошибок
148. **`console.assert`** — проверка условий в case.
149. **`console.trace`** — стек вызовов для отладки.
150. **`try...catch` внутри case** — обработка ошибок в отдельных кейсах.
