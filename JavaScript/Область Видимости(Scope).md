# Область видимости (Scope) в JavaScript

## Определения и базовые понятия
1. **Область видимости (Scope)** — контекст выполнения, определяющий доступность переменных, функций и объектов.
2. **Лексическое окружение (Lexical Environment)** — внутренняя структура движка, хранящая переменные и привязки.
3. **Окружение записи (Environment Record)** — объект, хранящий фактические переменные внутри лексического окружения.
4. **Внешнее лексическое окружение (Outer Environment)** — ссылка на родительскую область (для замыканий).
5. **Глобальный объект** — `window` (браузер), `global` (Node.js), `globalThis` (универсальный).

## Типы областей видимости
6. **Глобальная область** — доступна везде. Переменные объявлены вне функций и блоков.
7. **Функциональная область** — создаётся внутри функции. Доступна только внутри неё (`var`, `function`).
8. **Блочная область** — создаётся внутри `{}` для `let` и `const` (до ES6 только функциональная).
9. **Модульная область** — создаётся в ES-модулях. Переменные не попадают в глобальный объект.
10. **Область catch-блока** — создаётся внутри `catch (err) { }`.
11. **Область with (устаревшая)** — `with(obj) { }` (запрещена в strict mode).

## Объявление переменных и их области
12. **`var`** — функциональная область (или глобальная). Игнорирует блоки.
13. **`let`** — блочная область. Доступна только внутри блока `{}`.
14. **`const`** — блочная область. Требует инициализации, нельзя переприсвоить.
15. **`function` declaration** — всплывает в начало своей области (функциональной или глобальной).
16. **`function` expression** — подчиняется правилам переменной (var/let/const).
17. **`class` declaration** — блочная область, не всплывает (в отличие от функций).
18. **`import/export`** — модульная область (не попадают в глобальный объект).

## Всплытие (Hoisting)
19. **Hoisting (всплытие)** — поднятие объявлений в начало области до выполнения кода.
20. **Всплытие `var`** — объявление поднимается, инициализация остаётся на месте (`undefined`).
21. **Всплытие `function`** — объявление + определение поднимаются полностью.
22. **Всплытие `let`/`const`** — объявление поднимается, но инициализация не происходит (TDZ).
23. **Всплытие `class`** — объявление поднимается, но не инициализируется (TDZ).
24. **Порядок всплытия** — функции поднимаются выше переменных.

## Временная мёртвая зона (TDZ)
25. **TDZ (Temporal Dead Zone)** — период между входом в область и фактической инициализацией `let`/`const`.
26. **Доступ к переменной в TDZ** — вызывает `ReferenceError`.
27. **TDZ для `let`** — от начала блока до строки объявления.
28. **TDZ для `const`** — аналогично `let`, но требует инициализации при объявлении.
29. **TDZ для `class`** — класс недоступен до объявления.
30. **TDZ для параметров по умолчанию** — параметры не видят друг друга до инициализации.

## Цепочка областей (Scope Chain)
31. **Цепочка областей** — иерархия лексических окружений для поиска переменных.
32. **Поиск по цепочке** — движок ищет переменную в текущей области, затем во внешних, до глобальной.
33. **Переопределение** — переменная во внутренней области "затеняет" внешнюю (shadowing).
34. **Разрешение идентификаторов** — процесс поиска переменной по цепочке областей.
35. **Остановка поиска** — при нахождении переменной или достижении глобальной области.

## Затенение (Shadowing)
36. **Shadowing (затенение)** — объявление переменной с тем же именем во внутренней области.
37. **Затенение `var`** — `var` в блоке может быть видна за пределами блока (если не в функции).
38. **Затенение `let`/`const`** — `let` может затенять `var`, но не может затенять `let` в той же области.
39. **Затенение параметров** — переменная внутри функции затеняет параметр с тем же именем.
40. **Затенение глобальных переменных** — локальная переменная скрывает глобальную.

## Глобальная область
41. **Глобальная область в браузере** — `window` (или `window` как `globalThis`).
42. **Глобальная область в Node.js** — `global` (или `globalThis`).
43. **`var` в глобальной области** — создаёт свойство на `window` (в браузере).
44. **`let`/`const` в глобальной области** — не создают свойство на `window` (но доступны глобально).
45. **Необъявленные переменные** — в нестрогом режиме становятся свойствами `window` (опасно).
46. **`globalThis`** — универсальный глобальный объект (ES2020).

## Функциональная область
47. **Область функции** — создаётся при вызове функции (каждый вызов создаёт новую область).
48. **Параметры функции** — находятся в области функции (как локальные переменные).
49. **`var` внутри функции** — доступна во всей функции (не только в блоке).
50. **`let`/`const` внутри функции** — доступны только в блоке, где объявлены.
51. **Вложенные функции** — имеют доступ к переменным родительской функции (замыкание).

## Блочная область
52. **Блок** — `{ }` (if, for, while, switch, отдельный блок).
53. **`let` в блоке** — доступна только внутри этого блока.
54. **`const` в блоке** — доступна только внутри этого блока.
55. **`var` в блоке** — игнорирует блок, видна во всей функции/глобальной области.
56. **`function` в блоке** — поведение зависит от режима (в строгом — блочная, в нестрогом — может всплывать).

## Модульная область
57. **ES-модули** — каждая модуль имеет свою область (файл).
58. **`import`** — импортированные значения доступны только в модуле.
59. **`export`** — экспортированные значения доступны другим модулям.
60. **Глобальные переменные в модулях** — не попадают в `window` (изолированы).
61. **`import.meta`** — мета-информация о модуле (путь, URL).

## Strict Mode и область
62. **`"use strict"`** — включает строгий режим (меняет поведение области).
63. **`this` в глобальной области** — в строгом режиме `undefined` (в нестрогом — `window`).
64. **`delete` переменной** — в строгом режиме нельзя удалять переменные.
65. **Необъявленные переменные** — в строгом режиме вызывают `ReferenceError`.
66. **`with`** — запрещён в строгом режиме.
67. **`eval` в строгом режиме** — создаёт изолированную область (не загрязняет внешнюю).

## Область в циклах
68. **`var` в `for`** — видна за пределами цикла (функциональная область).
69. **`let` в `for`** — создаёт новую область на каждой итерации (для замыканий).
70. **`const` в `for`** — работает, но не может быть изменена в теле цикла.
71. **Проблема с `var` в цикле** — все итерации используют одну переменную (проблема с замыканиями).
72. **Решение через IIFE** — `(function(i) { setTimeout(() => console.log(i), 100); })(i)`.
73. **Решение через `let`** — `for (let i = 0; i < 3; i++) { setTimeout(() => console.log(i), 100); }`.

## Область в условных операторах
74. **`if` с `var`** — `var` видна за пределами `if` (в функции/глобальной).
75. **`if` с `let`/`const`** — видны только внутри `if`.
76. **`switch` с `let`/`const`** — видны во всём `switch` (блок не создаёт отдельную область без `{}`).

## Замыкания (Closures)
77. **Замыкание** — функция, сохраняющая доступ к области, в которой была создана.
78. **Сохранение внешней области** — даже после завершения внешней функции.
79. **Цепочка замыканий** — несколько вложенных функций сохраняют несколько областей.
80. **Память и замыкания** — замыкания могут приводить к утечкам памяти.
81. **Практическое использование** — приватные переменные, мемоизация, декораторы.

## Особенности `eval`
82. **`eval` в глобальной области** — выполняется в глобальной области (если вызван глобально).
83. **`eval` в функциональной области** — выполняется в текущей области (может создавать переменные).
84. **`eval` в строгом режиме** — выполняется в изолированной области (не видит внешние переменные).
85. **`eval` и область** — `eval` может изменять локальные переменные (опасно, избегать).
86. **`eval` и `var`** — создаёт переменные в текущей области (не в глобальной).

## Особенности `with` (устаревший)
87. **`with(obj)`** — добавляет свойства объекта в текущую область (запрещён в strict mode).
88. **Проблемы `with`** — неоднозначность, медленная работа, запрещён в модулях.

## Отладка области
89. **`console.log(variable)`** — проверка значения переменной.
90. **`debugger`** — остановка выполнения для инспекции области.
91. **`console.dir()`** — вывод структуры переменной.
92. **Стек вызовов (Call Stack)** — показывает цепочку областей.
93. **Инструменты разработчика** — вкладка Scope показывает текущие области.

## Продвинутые концепции
94. **Замыкание в циклах** — использование `let` или IIFE для сохранения значений.
95. **Динамическая область (Dynamic Scope)** — в JS нет, только лексическая (кроме `this`).
96. **Лексическая область (Lexical Scope)** — определяется местом объявления, не вызовом.
97. **`Function.prototype.bind` и область** — привязывает `this`, но не переменные.
98. **`call`/`apply` и область** — меняют `this`, но не область видимости.
99. **`new Function()` и область** — выполняется в глобальной области (не видит локальные переменные).
100. **Функции-стрелки и область** — не имеют своего `this`, берут из лексической области.

## Распространённые ошибки
101. **Ошибка: переменная не объявлена** — `ReferenceError: x is not defined`.
102. **Ошибка: доступ в TDZ** — `ReferenceError: Cannot access 'x' before initialization`.
103. **Ошибка: переопределение `let`** — `SyntaxError: Identifier 'x' has already been declared`.
104. **Ошибка: `const` без инициализации** — `SyntaxError: Missing initializer in const declaration`.
105. **Ошибка: присвоение `const`** — `TypeError: Assignment to constant variable`.
106. **Ошибка: использование `this` в глобальной области (strict)** — `undefined`.
107. **Ошибка: `var` в цикле с замыканием** — все итерации используют последнее значение.

## Практические примеры
108. **Модульный паттерн (IIFE)** — `(function() { var private = 1; return { get: () => private }; })()`.
109. **Паттерн "Объект настроек"** — `var config = (function() { var settings = {}; return { get: (key) => settings[key] }; })()`.
110. **Счётчик через замыкание** — `function counter() { let count = 0; return () => ++count; }`.
111. **Мемоизация через замыкание** — `function memoize(fn) { const cache = {}; return (arg) => cache[arg] ??= fn(arg); }`.
112. **Частичное применение** — `function partial(fn, ...args) { return (...rest) => fn(...args, ...rest); }`.
113. **Ограничение области через блок** — `{ let x = 10; } console.log(x); // ReferenceError`.
114. **Однократный вызов через замыкание** — `function once(fn) { let called = false; return (...args) => { if (!called) { called = true; return fn(...args); } }; }`.
115. **Создание приватных методов** — через замыкание и возврат объекта с методами.
116. **Изоляция кода** — использование блоков и IIFE для избегания конфликтов.

## Сравнение с другими языками
117. **Отличие от Java/C++** — в JS нет областей на уровне классов (до ES6).
118. **Отличие от Python** — в Python область блока (кроме функций), в JS до ES6 только функции.
119. **Отличие от C#** — в C# блочная область изначально, в JS с ES6.
120. **Отличие от PHP** — в PHP глобальные переменные не попадают в функции без `global`.

## Современные тренды
121. **Предпочтение `let`/`const` над `var`** — из-за блочной области и TDZ.
122. **Избегание глобальных переменных** — через модули и IIFE.
123. **Использование `const` по умолчанию** — для неизменяемых ссылок.
124. **Использование `let` для изменяемых** — внутри блоков.
125. **Отказ от `var`** — в современном коде не рекомендуется.
126. **Модульная архитектура** — изоляция областей через ES-модули.
127. **Ограничение доступа через замыкания** — для приватных данных.
128. **Использование `globalThis` для кроссплатформенности**.
129. **Использование `#` приватных полей в классах** (ES2022) — альтернатива замыканиям.
130. **`import.meta`** — для доступа к метаданным модуля.

## Оптимизация области
131. **Уменьшение цепочки областей** — меньше вложенности → быстрее поиск.
132. **Кэширование внешних переменных** — `const self = this` для ускорения.
133. **Избегание `eval` и `with`** — они ломают оптимизации.
134. **Использование `const` для локальных переменных** — улучшает производительность.
135. **Минимизация глобальных переменных** — ускоряет доступ.
